CHAPTER 01 · 30 QUESTIONS

API 與 HTTP 基礎

對應題目 1～30。先理解網路請求，再看 URL、方法、狀態碼與 JSON。

1. API 是什麼？ Q1～2

API（Application Programming Interface） 是讓不同程式依照約定互相溝通的介面。你可以把它想成餐廳菜單：App 發出要求，伺服器依規則提供資料或功能。

📱 Android App用戶端 Client
→
🌐 HTTP API規定請求格式
→
🖥 伺服器Server 處理請求

HTTP 是常見的網路通訊協定，定義 Client 如何送出 Request，以及 Server 如何傳回 Response。HTTPS 是透過 TLS 加密的 HTTP 通訊。

API 不是一種程式語言，也不一定要連網；這份教材討論的是最常見的 Web API。

2. Request 與 Response 的基本架構 Q29

① 發出請求Method + URL + Headers + 可選 Body
→
② 伺服器處理檢查驗證、讀寫資料
→
③ 回傳結果Status Code + Headers + 可選 Body
HTTP Request 範例 
POST /users HTTP/1.1
Host: api.example.com
Content-Type: application/json

{"name":"Amy","age":16}
HTTP Response 範例 
HTTP/1.1 201 Created
Content-Type: application/json

{"id":7,"name":"Amy","age":16}
  • Method：這次要做什麼，例如 GET / POST。
  • URL：要對哪個資源操作。
  • Headers：請求或回應的補充資訊，例如格式與驗證。
  • Body：傳輸的內容，不是每個請求或回應都有。
  • Status Code：伺服器回應結果的三位數狀態碼。

3. URL 基本架構 Q3～8

URL 用來指出網路資源的位置，常見形式：

https://api.example.com/users/7?active=true&lang=zh
紫色 Scheme / 協定綠色 Host / 網域橘色 Path / 路徑粉色 Query / 查詢參數
部分作用例子
Scheme指定通訊方式https
Host伺服器網域api.example.com
Port（可選）指定網路服務連接埠:8080
Path指定資源路徑/users/7
Query? 開始，& 分隔多個參數?q=cat&page=2
試著讀這段 URL：https://example.com/search?q=cat，其中 q=cat 是查詢參數，不是路徑或 HTTP 狀態碼。

4. GET / POST 基本概念 Q9～12

GET

通常用來取得資源，例如查詢使用者、取得文章。

GET /users

通常不透過 Request Body 傳參數，常使用 Path / Query。

POST

通常用來提交資料或建立資源，例如新增使用者。

POST /users

常把 JSON 資料放在 Request Body 中。

GET / POST 範例 
GET https://api.example.com/users?page=2

POST https://api.example.com/users
Content-Type: application/json

{"name":"Amy"}

常見其他方法：PUT 通常取代資源、PATCH 修改部分內容、DELETE 刪除資源。

注意：GET 不應設計成修改伺服器狀態的操作；POST 也不等於「保證成功新增」。真正結果要看伺服器規格與回傳狀態。

5. HTTP 狀態碼 Q13～23、30

1xx資訊回應
2xx成功
3xx重新導向
4xx用戶端錯誤
5xx伺服器錯誤
狀態碼名稱基本意思常見情境
200OK成功成功取得資料
201Created資源建立成功新增使用者成功
204No Content成功但沒有回應內容刪除後不回傳 Body
400Bad Request請求有問題參數格式錯誤
401Unauthorized未通過身分驗證缺少有效登入憑證
403Forbidden伺服器拒絕存取權限不足
404Not Found找不到目標資源路徑錯誤或資源不存在
500Internal Server Error伺服器內部錯誤後端程式出錯
超重要：401 = 身分驗證失敗／缺少驗證；403 = 伺服器拒絕存取；404 = 找不到資源；500 = 伺服器本身發生錯誤。拿到 404 先檢查 URL、Method、Path 和資源 ID。

6. JSON 與 Content-Type Q24～28

JSON 是常見的資料交換格式。物件（Object） 用大括號 { }，陣列（Array） 用中括號 [ ]。

JSON 範例 
{
  "name": "Amy",
  "age": 16,
  "isStudent": true,
  "skills": ["Kotlin", "Compose"],
  "nickname": null
}
  • 屬性名稱與字串值必須使用雙引號。
  • 數字不加引號；布林值為 true 或 false。
  • Content-Type: application/json 表示傳送內容的格式為 JSON。
  • JSON 不允許未加雙引號的鍵，也不允許單引號取代字串的雙引號。
考題 {"name":"Amy"} 是合法 JSON；{name:'Amy'} 不是。
CHAPTER 02 · 30 QUESTIONS

Kotlin 基本語法

對應題目 31～60。Android App 的主要程式語言之一。

7. 變數：val / var Q31～32

Kotlin 
val school = "資訊科"  // 不能重新指定
var score = 80         // 可以重新指定
score = 90

// school = "別的科"  // 編譯錯誤
val 代表變數綁定不可再被指定新值，不代表所指向的物件內容絕對不可變。新手可先記：能用 val 就優先用 val。

8. 常見型別 Q33～35

型別用途範例
Int整數val age = 16
Double雙精度浮點數val pi = 3.14
Float單精度浮點數val f = 1.5f
String文字val name = "Amy"
Char單一字元val letter = 'A'
Boolean真假val ok = true

Kotlin 通常能根據右邊的值自動推斷型別，例如 val x = 10 就會推斷為 Int。

9. 運算子 Q36～40、59

基本運算 
val a = 5 + 3       // 8
val b = 10 / 3      // 3：Int 除以 Int
val c = 10.0 / 3    // 3.3333...
val same = 5 == 5   // true
val both = true && false  // false
val either = true || false // true
val passed = 80 >= 60     // true

= 是指定值，== 是比較是否相等；&& 是 AND（兩邊都真），|| 是 OR（至少一邊真），! 是 NOT（反轉真假）。

10. if / when / 迴圈 Q41～45

條件與迴圈 
val age = 18
if (age >= 18) println("成年") else println("未成年")

val score = 80
val grade = when {
    score >= 90 -> "A"
    score >= 60 -> "通過"
    else -> "不通過"
}

for (i in 1..3) println(i) // 印出 1、2、3
repeat(5) { println("Hi") } // 5 次
var n = 0
while (n < 3) { n++ }

1..3 包含 1 和 3，所以共跑 3 次。while 只要條件為 true 就會繼續執行。

11. fun / return / println Q46～49

函式 
fun hello() {
    println("Hello")
}

fun add(a: Int, b: Int): Int {
    return a + b
}

val result = add(2, 3) // 5
hello() // 在標準輸出顯示 Hello 並換行

fun 宣告函式，a: Int 是參數與型別，括號後的 : Int 是回傳型別，return 傳回值並結束該函式。

12. 字串模板與註解 Q50、60

字串 
val name = "Amy"
val age = 16
println("Hi $name")       // Hi Amy
println("明年 ${age + 1} 歲") // 明年 17 歲

// 這是單行註解
/* 這是多行註解 */

$name 將變數值插入字串；需要表達式時用 ${...}。

13. List 與索引 Q51～53

清單 
val nums = listOf(1, 2, 3)
println(nums[0])    // 1：索引從 0 開始
println(nums.size)  // 3

val names = mutableListOf("Amy", "Ben")
names.add("Cindy") // 可變清單可以增加項目

listOf() 建立唯讀介面的清單；mutableListOf() 建立可修改清單。

14. Null Safety：?、?.、?: Q54～56

Nullable 
var name: String? = null   // 可以是 null
val length = name?.length // name 為 null 時得到 null
val display = name ?: "Guest" // null 就使用 Guest

name = "Amy"
println(name?.length)  // 3
String? 允許 null；?. 安全呼叫；?: Elvis 運算子提供備用值。新手先不要隨意使用 !!，它可能造成程式崩潰。

15. class / data class Q57～58

資料模型 
class Student(val name: String)

// API 收到的使用者資料可以用 data class 表示
data class User(val id: Int, val name: String)

val user = User(1, "Amy")
println(user.name) // Amy

class 定義類別，data class 適合用來表示資料，例如 API 回傳的使用者物件，也會自動產生 toString()、equals()、copy() 等功能。

Jetpack Compose 基本元件

對應題目 61～90。從 Text、Button 到 Row、Column，再認識 State 與 UI 更新。

16. Compose 是什麼？ Q61～62

Jetpack Compose 是 Android 的宣告式 UI 工具組。開發者描述「畫面應該長什麼樣子」，Compose 會根據目前狀態組合出畫面。

最簡單的 Composable 
import androidx.compose.runtime.Composable
import androidx.compose.material3.Text

@Composable
fun Greeting() {
    Text("Hello Compose!")
}
Hello Compose!

@Composable 標示可由 Compose 呼叫、用來描述 UI 的函式。

17. 常見 UI 元件 Q63～65、76～81

Text
Hello!

顯示文字：Text("Hello!")

Button + onClick
點了 0 次

點擊後執行 onClick 的動作。

TextField / OutlinedTextField
你好！

接受輸入；Outlined 版本主要差在邊框樣式。

Image / Icon
🖼️★ 這裡是 Icon 示意

Image 顯示圖片；Icon 顯示圖示。

Checkbox

適合勾選／取消勾選。

Switch
關閉

適合二元開／關設定。

Compose 元件示例 
@Composable
fun SimpleForm() {
    var name by remember { mutableStateOf("") }
    var checked by remember { mutableStateOf(false) }
    Column {
        Text("請輸入姓名")
        OutlinedTextField(
            value = name,
            onValueChange = { name = it },
            label = { Text("姓名") }
        )
        Checkbox(checked = checked, onCheckedChange = { checked = it })
        Button(onClick = { println(name) }) {
            Text("送出")
        }
    }
}
上例需匯入對應的 Compose Material3、runtime、layout 與 getValue/setValue 等套件；可在 Android Studio IDE 自動匯入。

19. Modifier：尺寸、間距、點擊 Q69～75、89

寫法用途
Modifier.padding(16.dp)設定內距
Modifier.fillMaxWidth()填滿可用寬度
Modifier.fillMaxSize()填滿可用寬、高
Modifier.size(48.dp)指定寬與高
Spacer(Modifier.height(8.dp))垂直間距
Modifier.clickable { ... }設定點擊動作
16.dp密度獨立的尺寸單位
18.sp用於文字大小、考慮使用者字體縮放
Modifier 範例 
Column(modifier = Modifier.padding(16.dp)) {
    Text("Hello", fontSize = 20.sp)
    Spacer(modifier = Modifier.height(8.dp))
    Button(onClick = {}, modifier = Modifier.fillMaxWidth()) {
        Text("送出")
    }
}
Modifier 的排列順序可能影響畫面。例如先 padding 再 background，與先 background 再 padding，背景覆蓋的範圍可能不同。

20. State、remember、重組 Q84～86

Compose 不是「每按一次就手動找文字改掉」。通常是修改 State（狀態），Compose 自動更新讀取該狀態的相關 UI。

計數器 
@Composable
fun Counter() {
    var count by remember { mutableStateOf(0) }
    Column {
        Text("已點擊 $count 次")
        Button(onClick = { count++ }) {
            Text("+1")
        }
    }
}
已點擊 0 次
  • mutableStateOf(0)：建立 Compose 可觀察的狀態值。
  • remember { ... }：在重組期間保留值。
  • Recomposition（重組）：狀態變動時，Compose 重新執行需要更新的 Composable 內容。
  • 若要跨 Activity 重建（例如旋轉畫面）保留簡單可儲存狀態，可研究 rememberSaveable。

24. 把 API 資料顯示到 Compose Q96、98～100

Button 點擊UI 事件
→
呼叫 APICoroutine + Retrofit
→
取得 JSON轉換成 Kotlin 資料模型
→
更新 StateCompose 自動更新 UI

Retrofit 是常見的 Android HTTP API 客戶端程式庫。網路請求不應阻塞主執行緒，通常使用 Kotlin Coroutine 的 suspend 呼叫，並由 ViewModel 等元件管理 UI State。

Manifest 權限宣告 
<uses-permission android:name="android.permission.INTERNET" />
Retrofit 概念示意 
// Kotlin：在搭配 Retrofit、JSON converter 與依賴設定後
// 假設 API 回傳 {"id":1,"name":"Amy"}
data class User(val id: Int, val name: String)

interface UserApi {
    @GET("users/1")
    suspend fun getUser(): User
}

// 在 ViewModel 協程中呼叫 api.getUser()
// 取得結果後再更新 UI 使用的 State
上面是架構示意，並非可直接貼上就能執行的完整 App；實作還需要 Retrofit 相依套件、Retrofit 實例、Converter、錯誤處理與網路服務位址。api.example.com 僅為示範網址。

25. 常見錯誤排查

現象先檢查什麼
API 404URL、路徑、HTTP Method、資源 ID
API 401 / 403身分驗證、存取權限、Token 是否有效
API 500伺服器記錄；用戶端應顯示錯誤與重試
JSON 解析失敗欄位名稱、型別、null、回傳格式
按鈕後畫面不變是否更新 Compose 可觀察的 State
網路失敗INTERNET 權限、網路、HTTPS、模擬器連線
App 畫面卡住是否在主執行緒執行耗時工作
測驗很常考：「404 是網頁或資源找不到，不是伺服器內部錯誤」、「更新 Compose 的 State 後，相關畫面才會跟著變」。
